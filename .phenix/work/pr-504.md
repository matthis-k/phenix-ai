# PR 504 working state

## Current state

Base: current `main` (`3f34f801`)
Phase: implementation

## Decisions

- #503/#505 are merged and authoritative for value/capability and client-tool semantics.
- `clients/nvim` is the canonical frontend source. Only `phenix_nvim.runtime` owns native `phenix` client userdata.
- Standard ACP session helpers are not a completed-client fallback. Production #504 uses the fixed application descriptor plus `phenix.sessions.state` SDK observable.
- `phenix-harness` owns the configured application worker and packaged `phenix-acp` executable; `phenix-acp-stdio` remains transport/channel infrastructure.
- Session/transcript state is `SessionProjectionState` at SDK path `phenix.sessions.state`.
- Permission/elicitation handlers are client-owned callable refs installed through one fixed application operation.
- Pending edit review is execution-owned durable state; workspace applies accepted mutations before runtime reports `Accepted`.
- Prompt delivery uses application `Content::{Text, Resource, Image}` exactly. Frontend Lua does not create a parallel wire shape.
- The byte-only model inference ABI is not extended with text conventions. Tool-result continuation, retained typed turns, multimodal model input, and provider streaming wait for `spec/model-turn-protocol.md` implementation.

## Findings

- The configured application worker can invoke `phenix.agent-loop@1`, but the packaged ACP product currently activates no `phenix.models.inference@1` provider matching runtime targets such as `openai-codex` and `opencode-go`.
- `phenix.models` also requires each selected provider plugin to be marked authenticated before invocation. Product provider assembly and authentication must use the ordinary provider/plugin architecture rather than an ACP-only backend path.
- `phenix-backend-native` contains the current native OpenAI Codex/API/provider implementation, but it is a passive backend library rather than a model-inference plugin.
- `spec/model-turn-protocol.md` remains specification-only. The current `ModelInferenceRequest` has byte input and can return tool calls, but cannot represent typed tool results in a continuation turn.
- Exact-head Clippy previously reported `clippy::double_must_use` on `phenix-client-acp::DescriptorExtensions::advertised_capabilities`; this remains an actionable CI cleanup if it reproduces on the latest head.

## Progress

- Added passive session projection, review, and interaction-handler types plus descriptor/generated fixture updates.
- Added the configured Harness ACP process and fixed 64/64/256 application, callback, and event queue policy.
- Published `phenix.sessions.state` and wired full/diff subscription recovery in the Neovim runtime.
- Replaced Neovim ACP session-helper semantics with descriptor-backed create/list/resume/prompt/cancel operations and exact `Content::{Text, Resource, Image}` compose mapping.
- Added `phenix.defer(start)` and current-generation interaction handler admission. Permission UI is deferred and returns only valid permission responses.
- Prompt dispatch is now asynchronous. The application loop retains the prompt reply while a background execution invokes `phenix.agent-loop@1`, so cancel and other application requests remain serviceable.
- The worker journals execution `Running`, assistant output, `Completed`/`Failed`/`Cancelled`, and responds to the prompt only after execution finishes. Application-level cancel now targets a real active execution.
- Model execution rejects Resource/Image content and returned tool calls explicitly until the typed model-turn contract can represent them correctly.
- Replaced the ad hoc transcript reducer with deterministic `session:<sid>:...` identities over actual `SessionUpdate`/`SessionChange` shapes. Assistant deltas mutate one execution streaming node, tool results mutate the original call node, review nodes use review IDs, and unknown tool-result identities fail reduction instead of inventing state.
- Added a selected-session transcript controller. Normal contiguous observable changes update only changed extmark-backed nodes; session changes or reducer invariant failures rebuild from runtime projection state.
- Strengthened the packaged Neovim check so it verifies the substituted `phenix-acp` path, establishes a real packaged ACP connection, creates a durable session, and verifies the state database is written.
- PR body now records the async worker and provider/model-turn blockers instead of describing prompt execution as still fake.
