# PR 504 working state

## Current state

Base: current `main` (`3f34f801`)
Phase: finalization / dependency boundary

## Decisions

- #503/#505 are merged and authoritative for value/capability and client-tool semantics.
- `clients/nvim` is the canonical frontend source. Only `phenix_nvim.runtime` imports native `phenix`.
- Standard ACP session helpers are not a completed-client fallback. Production #504 uses the fixed application descriptor plus `phenix.sessions.state` SDK observable.
- `phenix-harness` owns the configured application worker and packaged `phenix-acp` executable; `phenix-acp-stdio` remains transport/channel infrastructure.
- Session/transcript state is `SessionProjectionState` at SDK path `phenix.sessions.state`.
- Permission/elicitation handlers are client-owned callable refs installed through one fixed application operation.
- Pending edit review is execution-owned durable state; workspace applies accepted mutations before runtime reports `Accepted`.
- Prompt delivery uses application `Content::{Text, Resource, Image}` exactly. Frontend Lua does not create a parallel wire shape.
- The byte-only model inference ABI is not extended with text conventions. Tool-result continuation, retained typed turns, multimodal model input, and provider streaming wait for the central model-turn/invocation implementation rather than creating a #504-only path.
- Real provider/model dispatch must use the ordinary provider/plugin and central invocation architecture. Do not revive an ACP-only or legacy backend shortcut.

## Findings

- The configured application worker can invoke `phenix.agent-loop@1`, but this branch's default Harness composition activates routing/execution without a model-inference provider matching configured targets such as `openai-codex` and `opencode-go`.
- `phenix.models` also requires selected providers to be authenticated before invocation.
- The active model/runtime migration is now represented by #559-#563. #563 explicitly owns default invocation composition and migration away from legacy `ModelCommand::Invoke`; duplicating that work inside #504 would create a competing invocation path.
- `spec/model-turn-protocol.md` remains specification-only on this branch. The current byte input cannot represent typed tool-result continuation or proper multimodal turns.
- Elicitation `Accepted.value` is structurally `Any`, so Lua dynamic values lose distinctions such as U64/Table/unit Variant while crossing the generic boundary. `phenix-application-interface` now owns `normalize_elicitation_response` to restore the exact request schema. The frontend form also validates the exact supported subset. The final callback-consumption hook must call the application normalizer when runtime elicitation becomes live; do not claim generic `Any` conversion itself preserves the dependent type.
- Exact-head GitHub workflows can require manual approval. A prior head returned `action_required` with zero jobs; this is an approval gate, not a code failure.

## Progress

- Added passive session projection, review, and interaction-handler types plus descriptor/generated fixture updates.
- Added the configured Harness ACP process and fixed 64/64/256 application, callback, and event queue policy.
- Published `phenix.sessions.state` and wired full/diff subscription recovery in the Neovim runtime.
- Replaced Neovim ACP session-helper semantics with descriptor-backed create/list/resume/close/prompt/cancel operations and exact `Content::{Text, Resource, Image}` compose mapping.
- Added `phenix.defer(start)` and current-generation interaction handler admission. Disconnect retirement and bounded deferred callback semantics are covered.
- Added dependency-free permission and elicitation UI. Permission close returns `Cancelled`; elicitation supports string/bool/i64/u64/f64, scalar option, recursive table, unit variants, and supported lists. Invalid fields retry in-place; unsupported schemas fail explicitly with `unsupported_schema`.
- Added application-owned elicitation normalization and tests that reconstruct exact dependent Phenix values from dynamic language values.
- Prompt dispatch is asynchronous. The application loop retains the prompt reply while a background execution invokes `phenix.agent-loop@1`, so cancel and other application requests remain serviceable.
- The worker journals execution `Running`, assistant output, `Completed`/`Failed`/`Cancelled`, and responds to the prompt only after execution finishes. Application-level cancel targets a real active execution.
- Model execution rejects Resource/Image content and returned tool calls explicitly until the typed model-turn contract can represent them correctly.
- Replaced the ad hoc transcript reducer with deterministic `session:<sid>:...` identities over actual `SessionUpdate`/`SessionChange` shapes. Assistant deltas mutate one execution streaming node, tool results mutate the original call node, review nodes use review IDs, and unknown tool-result identities fail reduction instead of inventing state.
- Added a selected-session transcript controller. Normal contiguous observable changes update only changed extmark-backed nodes; session changes or reducer invariant failures rebuild from runtime projection state.
- Status derives execution state from the cached session projection only.
- Added image preview ownership using `vim.ui.img.set/del`, immutable attachment bytes, extmark/window tracking, and cleanup on marker removal, sidebar close, compose clear, or buffer teardown. Sending does not depend on preview availability.
- Execution review now owns durable prepared-review state. Accept performs the exact version-checked workspace write before marking Accepted; conflicts become Conflicted; Reject does not mutate files; restart behavior is covered.
- Frontend review actions use the current returned review/revision and wait for runtime results.
- Packaged Neovim checks verify the substituted packaged `phenix-acp`, run headless transcript/image/interaction regressions, create a durable session through one packaged ACP process, reconnect through a second process using the same state DB, resume the exact session, and verify runtime projection reconstruction.
- Removed the earlier Clippy `double_must_use` failure and stabilized the ACP extension-event regression.
