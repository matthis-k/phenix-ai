# PR 504 working state

## Current state

Phase: implementation

## Decisions

- #503/#505 are merged and authoritative for value/capability and client-tool semantics.
- `clients/nvim` is the canonical frontend source. Only `phenix_nvim.runtime` owns native `phenix` client userdata.
- Standard ACP session helpers are not a completed-client fallback. Production #504 uses the fixed application descriptor plus `phenix.sessions.state` SDK observable.
- `phenix-harness` owns the configured application worker and packaged `phenix-acp` executable; `phenix-acp-stdio` remains transport/channel infrastructure.
- Session/transcript state is `SessionProjectionState` at SDK path `phenix.sessions.state`.
- Permission/elicitation handlers are client-owned callable refs installed through one fixed application operation.
- Pending edit review is execution-owned durable state; workspace applies accepted mutations before runtime reports `Accepted`.
- Prompt delivery uses application `Content::{Text, Resource, Image}` exactly. Frontend Lua does not create a parallel wire shape.
- The implementation spec fixes queue capacities, reducer/gap behavior, transcript node identity, compose invariants, supported built-in form schema subset, packaging, tests, and implementation order.
- No architectural choice is intentionally deferred.

## Findings

- Consistency review: native lifted callbacks currently convert an immediate return value. The implementation spec defines host-local deferred completion for asynchronous UI without changing the generic wire ABI.
- The spec fixes read/subscribe baseline races, buffered update deduplication after repair, rename metadata projection, and application-worker progress while a prompt is pending.
- Native Lua binding already provides `client:sdk()`, `client:application()`, bounded polling, request handles, generic callable lifting, and #505 tool authoring.
- Generic SDK observable machinery already exists in `phenix-core`; production session contribution is the missing implementation.
- `phenix-acp-stdio` already owns the bounded typed channel and ACP server. The configured Harness application worker/executable is the missing implementation.
- Current frontend scaffolding already has separate transcript/compose buffers, stable compose snapshots, image presentation fallback, and structured review presentation scaffolding.
- Current `main` changed Core/Harness/library mechanics after the original #504 compaction. The branch was rebuilt on `3f34f801` before deeper worker implementation; #504 is no longer behind main at that point.

## Progress

- Added passive `SessionProjection` / `SessionProjectionState` types and review / interaction-handler structs and enums with structural round-trip tests.
- `SessionChange::Review` is intentionally still pending so the descriptor change, serialized descriptor, and generated Rust fixture can land atomically.
- Started `phenix-harness/src/application.rs` with the fixed 64/64/256 queue capacities and a projection reducer covering create, full-resume replacement, rename projection, missing-session repair, and sequence-gap repair signals.
- Added the Harness dependency on `phenix-application-interface`; repository maintenance owns the corresponding deterministic `Cargo.lock` refresh.
- Replaced the Neovim ACP session-helper path with descriptor-backed application operations for create, list, resume, prompt, and cancel. Compose items now map directly to `Content::{Text, Resource, Image}`.
- Added the SDK `phenix.sessions.state` read/listen path to the Neovim runtime. It keeps one local subscription generation, accepts full baselines and root replacement diffs, and repairs through a fresh `get()` plus initial-full subscription whenever a delivery cannot be applied safely.
- Added the configured Harness ACP process: `phenix-acp` activates the default suite, materializes the production SDK over the projection store, serves the 64/64/256 bounded queues, admits interaction callables for the active client generation, and retires handlers and client capabilities on disconnect.
- Added session-backed descriptor prompt/cancel dispatch. Prompt preserves the full `Content` sequence in the durable session journal and projection while execution streaming remains the next application-worker increment.
- Exposed `packages.<system>.phenix-acp` and substitutes that executable into the packaged Neovim client's default command while retaining the user override.
- Added `phenix.defer(start)` in the native binding. A lifted client callback can now retain one bounded reply handle and settle it later from the existing poll path; immediate callbacks remain unchanged and stale or repeated settlements are ignored.
