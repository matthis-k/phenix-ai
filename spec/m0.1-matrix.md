## Mechanism review

| Mechanism | Executable need | Owner and lifetime | Simpler alternative |
| --- | --- | --- | --- |
| Per-caller binding key | Choice and exact clients select different implementations | Prepared immutable map | A global operation key forces both clients to the same provider |
| Fixed enhanced import kind | An external client can omit one service and require an exact provider for another | Macro-generated descriptor | Handwritten runtime manifests duplicate annotations |
| Finite Authority | Relay must not widen operations or resource names granted by its caller | Root handle and synchronous call frames | Checking a resource only at startup permits a descendant effect to escape |
| Scoped host messages | Independent SDK needs attenuation without changing ABI 1.0 layouts | Existing authenticated callback | Adding unchecked trailing pointers would break frozen native tables |
| Resource context query | Provider must know the host-admitted resource without trusting a domain request string | Current authenticated call frame | Core parsing fixture payload fields would introduce domain-specific dispatch |
| Required cycle traversal | Installed required dependencies must reject a deterministic cycle before loading | Preparation only | Runtime reentrancy rejection alone does not prove valid startup dependencies |

There is no second resolver, execution engine or authority owner. Nix builds fixtures and runs checks; it does not perform provider selection. The original synchronous native lifecycle and buffer ownership remain in use.

M0.2 starts only after the M0.1 gate passes. Ticket/lease contracts must then be frozen before adding async execution.
