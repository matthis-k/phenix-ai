# M0.2 pending import ownership

This addendum freezes pending imports before implementing them. It extends ABI 2's scoped HostApi commands. It retains the same resolver, dispatcher, portable encoding and reply release rules.

## Authoring and host commands

`PendingHost::begin<O>` returns an immediate typed result or an opaque `PendingImport<O>`. `begin_scoped<O>` narrows the existing operation/resource authority. The handle has no Portable or serialization implementation and cannot cross threads. Each poll or cancel requires the current PendingHost. The stored handle never preserves an expired host scope.

The fixed command keys are `phenix.host.pending.begin.v1`, `phenix.host.pending.scoped.v1`, `phenix.host.pending.poll.v1` and `phenix.host.pending.cancel.v1`. Begin carries operation String and request Bytes. Scoped begin uses the existing ScopedRequest encoding. Poll and cancel carry operation String and ticket U64 in an exact map. These U64 values belong to the authenticated host protocol, not contract userdata or portable capabilities.

Begin returns ordinary typed status 0, 1 or 2 for an immediate result. Status 3 carries a child ticket U64. Poll returns a typed result only after physical quiescence, then releases the child record. Status 3 with Null means still pending. Status 4 with Null means the child was cancelled and is quiescent. Status 5 with Null means draining without another result. Cancel returns status 0 with a Bool quiescence summary. ABI 2 host command failures use status 5 with a typed Failure payload. They do not settle or consume an imported handle and do not prove quiescence. Status 2 from a successful poll command is a delivered child failure after quiescence. The ABI 2 host callback also uses status 5 for scope/thread rejection before reading inputs. Ordinary synchronous imports normalize those host failures for the existing typed CallResult. Every reply transfers its owned buffer once.

## Ownership and settlement

Each child binds its kernel, root, parent ticket, selected caller and operation. The kernel authenticates the current admission-thread frame before decoding a command. It rejects a handle from another parent, root, kernel or operation before entering native code. Begin resolves the caller's declared import through the existing frozen binding map and enters the existing effect boundary. Synchronous-only host calls still reject pending providers before native entry.

Each native pending entry records its current ticket in that call frame. Child wakes notify both child and ancestor polling requests through thread-safe notification references. The registry retains no Kernel address. Removing a permit rejects late traffic before accessing notification state.

Cancellation marks the parent before recursively requesting child cancellation. It revokes all protected host commands. Parent cancel hooks clean their own native work; the kernel owns cancellation and draining of imported work. Failed calls also revoke effects during physical draining. A cancelled or failed parent cannot restore child effect authority by polling.

Each ticket distinguishes its native quiescence claim from the quiescence of its owned children. Its physical lease remains live until both are quiet. Returning a completion while a child remains live is a protocol failure and retains the parent's image. Polling a native-quiescent parent never reenters its native poll hook. Draining polls outstanding child work through fresh revoked scopes.

An imported terminal result is delivered once, after quiescence. Caller drop marks the whole owned ticket tree abandoned, requests cancellation and keeps admission pinned until every physical lease is quiet. Root release also releases quiet descendants. Uncooperative children block ordered stop and safe unload of their parents and selected dependencies.

## Required proof

An independent SDK-only pending consumer imports the native worker service. Tests must cover immediate and pending provider selection, typed completion and errors, child wakes reaching the parent, wrong owner, stored authority attenuation, cancellation before descendant effects, noncooperative child leases, caller-drop tree draining and completion with a live child. Existing root, lifecycle and CLI checks must continue to pass.

The kernel needs child ownership because a plugin cannot authenticate another call's scope or keep its provider's image resident after a parent releases its result. The fixture supplies its service behavior and worker coordination outside Core.
