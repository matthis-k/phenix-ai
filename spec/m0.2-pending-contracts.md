# M0.2 pending native contract

This addendum freezes the native pending-call slice before implementation. The lifecycle addendum remains binding. Full M0.2 also requires pending imports and their parent/child cancellation tests. This slice does not accept that gate.

## ABI and authoring

Pending plugins declare ABI 2.0, feature bit 1, execution `pending`. The descriptor uses fixed `phenix.pending-operation.v1` Provide contributions. Contract identity, schemas and owned buffer encoding remain shared with synchronous plugins. An ABI 2 plugin exports pending operations only and may import synchronous operations. Offline validation rejects other profiles before loading.

`phenix_native_v2` returns a 56-byte C table on the selected Linux target. Its entries are create, invoke, stop, poll and cancel after the 16-byte header. Invoke receives instance, pending host, key and input. Poll and cancel receive instance, pending host and key. Create and stop retain ABI 1 buffer rules.

The 40-byte pending host contains the 16-byte synchronous HostApi followed by ticket, permit and wake callback. `wake(permit, ticket) -> u32` returns 0 when accepted and 1 when rejected. It only requests polling. It never supplies results or calls protected host effects. Owned replies retain producer release exactly once. Pending replies accept these statuses:

| Status | Meaning | Physical work |
| --- | --- | --- |
| 0 | Typed completion | Quiescent |
| 1 | Declared domain error | Quiescent |
| 2 | Kernel failure, including caught panic | May remain live |
| 3 | Pending, payload Null | Live |
| 4 | Quiescent after cancellation, payload Null | Quiescent |
| 5 | Explicit kernel failure | Quiescent |

Malformed replies cannot prove quiescence. A plugin claims quiescence only after all its native work has stopped. Poll may return 0, 1 or 5 after cancellation; the kernel discards that result while accepting its quiescence claim.

The SDK generates descriptors and all table glue from matching `#[pending(Op)]`, `#[poll(Op)]` and `#[cancel(Op)]` functions. Start returns typed `PendingResult<Response, Error>` with Pending or Ready. Poll returns the same type. Cancel returns `Result<bool, Failure>` where true proves quiescence. Rust async functions are outside this native profile.

## Tickets, threading and authority

The kernel owns opaque, nonportable tickets. Each ticket binds one kernel, root, selected provider, operation, frozen authority and resource. A stateful instance has at most one physical pending call. Calls enter the existing dispatcher, schema checks and effect authority checks. Synchronous imports cannot enter pending providers until the typed pending-import extension exists; rejection occurs before invocation.

Created and Running precede the first native entry. Pending may transition once to Ready, Failed or Cancelled. Only native quiescence permits physical release. A completed result is delivered once. Wrong kernel, wrong root, wrong ticket, repeated settlement and repeated cancellation reject before native entry. A cancelled ticket can still be polled to drain physical work without settling again.

Invoke, poll, cancel and all protected imports run on the admission thread. Each native entry gets a fresh synchronous scope. Worker threads may copy a wake permit. That permit authorizes only wake on its bound ticket. The process-wide wake registry stores thread-safe notification state, never a Kernel address. Releasing or destroying a ticket removes the permit. Forged, mismatched and late wake calls reject without accessing retired host state.

Poll restores the ticket's frozen authority and resource. Cancellation revokes protected host imports before entering cancel or later drain polls. Dropping the caller requests cancellation, but retains its admission pin while physical work remains. Trusted drain polls may release cancelled calls after quiescence.

## Executable leases and inspection

Each live ticket retains its selected native instance and executable image. Shutdown rejects while any physical lease remains and reports ticket and provider blockers. Cancellation, wake, a result channel closing and caller drop do not permit unload. If the kernel itself is dropped with noncooperative work, it invalidates all wake permits and retains native images rather than calling stop or dlclose on live code. Dependencies remain resident with those images. This deliberate retention is visible before destruction and may last until process exit.

Inspection adds versioned pending summaries with logical state, quiescence, wake requests and physical lease counts. Capability tokens and permit values remain private. A non-AI worker fixture must prove completion, cancellation before protected effects, delayed wake rejection, wrong owner, repeated settlement, caller-drop draining and blocked unload. Worker coordination uses channels or joins rather than timing assumptions.

The kernel owns this mechanism because an ordinary plugin cannot authenticate host scopes or keep another plugin's executable mapping resident after the caller releases it.
