## Mechanism review

The only new kernel behavior is ordered ownership of already selected native instances. The independent lifecycle consumer needs its required provider to start first and to remain acquired until consumer cleanup finishes. A plugin cannot own other loader images or safely roll back the kernel's acquisitions. The resolver's existing required graph supplies the order; annotations and injected behavior remain in SDK plugins. There is no new dispatcher, provider resolution path, scheduler or authority owner.

Next tasks are dependency ordered: freeze pending ABI/ticket semantics; implement one native pending root with wake/poll and explicit quiescence; prove cancellation, late callbacks and blocking leases; add typed pending import propagation and draining; accept M0.2; freeze and implement M0.3 generation identity and selection; complete M0.4 conformance.
