# M0.4 product acceptance

M0.4 adds packaging and evidence checks. It adds no kernel mechanism. Acceptance requires one pinned `nix flake check -L` run containing every prior gate, a standalone public SDK build, production closure inspection and an integrated evidence product.

The SDK gate builds and tests only the distributed contract, macros and SDK sources. Private kernel, artifact and conformance sources are physically absent. Native fixture products use their own Cargo workspace and generated annotations. Revision libraries deliberately share a Rust crate name so their generated provenance and descriptors are identical across executable revisions; Nix reads library filenames from each Cargo manifest.

The shipping gate depends on the exact kernel, SDK check and complete conformance product. It parses every JSON report, rejects a missing gate, verifies production closure membership and checks fixture source files for handwritten descriptor or native-entry registration. It records realized Nix paths, production files, closure members and parsed evidence files. The default package contains the kernel. Demo, fixtures, SDK source and conformance products are separate.

The release evidence product includes every gate's output. CI also records the exact commit and run ID and uploads the complete realized evidence. Final acceptance must cite the successful exact-head run; local results alone do not certify CI acceptance.
