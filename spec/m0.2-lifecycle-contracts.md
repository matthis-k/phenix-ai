# M0.2 lifecycle contract freeze

This addendum freezes the first M0.2 implementation slice after all six M0.1 local Nix gates passed on `76c874c51cebc8e9affa28288a0f672e29e46e9e`. Exact-head CI and milestone acceptance remain separate recorded gates. This slice implements failure-atomic synchronous start/stop; it does not accept the full asynchronous milestone.

## SDK declarations and ownership

An optional `#[start]` function has signature `fn(&mut State) -> Result<(), Failure>`; an optional `#[stop]` function has the same signature. Each annotation may appear once. The macro owns create/stop glue; hooks have no host scope, imports, root-admission API or authority. Hook presence is an implementation detail of the existing ABI 1.0 create/stop contract and introduces no descriptor contribution or handwritten registration table. Public operation declarations remain the only source of contract metadata.

Create first constructs the default state, then runs start. On a recoverable start failure it invokes stop once for partial-start cleanup, destroys the state and returns the original typed start failure with a null output instance. Cleanup failure cannot replace the first failure. State destructors remain responsible for their owned Rust resources. A caught start panic takes the same cleanup path. Cleanup panic is caught. A process-fatal failure cannot promise cleanup.

For an acquired instance, stop takes ownership once, runs the stop hook, and destroys state even if the hook reports failure or panics. Repeated native stop rejects before reentering the plugin. The kernel never retries an acquired stop after an error. These guarantees describe synchronous hooks only; they must not be used to authorize unloading a plugin with physically live asynchronous work.

## Dependency ordering and rollback

Composition preparation computes one deterministic startup order from its already frozen required-import bindings. Providers precede consumers; sorted plugin IDs and operation keys break independent ties. Optional imports do not establish required startup dependencies. The existing required-cycle traversal supplies both cycle rejection and order, without a second resolver. The minimal M0.0 deployment profile retains its synchronous runtime-cycle conformance; it does not claim dependency lifecycle ordering.

Before the first constructor, load rechecks every artifact. Each successfully created instance is appended to the acquired list. A later startup failure stops all acquired instances in reverse startup order before returning the original failure. A failed instance's partial cleanup happens inside its macro-generated create function. No root can be admitted during startup or rollback.

Explicit trusted `Kernel::shutdown(&self)` rejects while a root is admitted, then consumes acquired instances in reverse order. It attempts every stop even if one fails, records each typed failure, and returns the first failure. Repeated shutdown succeeds without repeating stop. Admission after shutdown rejects. Kernel destruction uses the same acquired order. Plugin host APIs cannot call shutdown. `phenix.inspect.v2` gains additive lifecycle fields for order, stopped state and stop failures; it reveals no capability tokens.

## Executable need and acceptance

Two independently built SDK-only lifecycle plugins use IDs whose lexical order is the opposite of their required dependency. Their hooks append start/stop/drop observations to an explicit conformance trace; consumer start/stop can return typed errors or panic. The conformance process checks real native invocation, dependency order, reverse normal and drop shutdown, partial-start cleanup, rollback despite cleanup failure, failed stop destruction, active-root shutdown rejection, post-shutdown admission rejection, and no double stop. The trace is a test fixture, not kernel instrumentation or domain dispatch.

The kernel intrinsic is ordered native instance ownership: an ordinary plugin cannot safely own the loader's acquired images or roll back another plugin. Hooks and test trace behavior stay in public SDK plugins. This implementation adds neither async tickets nor another invocation path.

## Remaining M0.2 gate

Pending calls, wake/poll, exactly-once logical settlement, cancellation, callback permits, physical leases, blocked unload and pending import propagation remain unimplemented. Their ABI and ticket-state contract must be frozen before their implementation. Full M0.2 and M0.3 cannot be accepted from synchronous lifecycle tests.
