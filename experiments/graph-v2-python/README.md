# Graph V2 + Python language adapter verification (isolated)

Tests the **actual** Phenix graph-v2 scheduler, not a mock callback and not the graph-v1/P1 execution path.

Source: Python plugin and PyO3 ABI-3 `.so` fixture copied from experimental [#1181](https://github.com/matthis-k/phenix-ai/pull/1181), including Python `@plugin`, `@expose` and `Host.invoke`. Rust provider reuses the independently compiled `examples/provider` artifact. The native host `.so` uses normal `phenix_sdk::plugin` and supplies a call-local Python host bridge; it **does not** modify the kernel ABI or create a second dispatcher.

Both independently compiled native fixtures embed `.phenix.graph` at link time. Their shared `graph-build.rs` uses public `phenix-contract` and the example contracts' generated operation definitions to obtain canonical `ValueSchema` request/response/error metadata. `GraphContributionV2::native_section()` normalizes, validates, bounds and frames the declaration. Exported `#[used]` statics include the generated bytes; no private kernel build dependency, objcopy injection or ABI revision is involved. The Rust fixture reuses the example provider implementation without changing the normal example artifact.

The runner verifies genuine `phenix-describe`-packaged artifacts offline, checks their embedded declarations against an independent descriptor-derived expectation, then invokes `Prepared::prepare_graph_v2`, `Kernel::begin_action_scoped`, and `GraphExecution::pump`. Only the schema-spoof negative rewrites an existing graph section and updates its executable digest. Trusted topology, source/operation attestations, delivery grants and composition authority remain outside authored metadata.

**Remaining authoring gap:** graph identities, source, nodes, edges and Python-to-contract mappings are manually authored in Rust build tooling. Python annotations do not generate graph declarations or contract schemas. This bounded embedding step is not the full typed graph builder, Python annotation compiler, subgraph API or production language adapter.

Both explicit graph wiring **Source → Python Invoke → Rust Invoke** and a nested Python `host.invoke` call to the Rust provider are covered. Nested calls stay *inside* the Python graph node; they are not a second graph node unless explicitly wired as such.

## Tested cases

- Positive: real typed Python output crosses a Graph V2 Flow edge and is delivered to a Rust Invoke; repeated invocations; nested Python Host.invoke to the same real selected Rust provider.
- Offline negative: missing/wrong provider selection; missing cross-plugin topology or delivery grants; missing source attestation; spoofed graph Invoke request schema.
- Runtime negative: malformed source payload; hidden Python method, Python exception and malformed return; unauthorized host operation, expired Host handle, native Rust panic in graph or nested call; domain error stops downstream graph node.
- Liveness: synchronous graph finishes and releases scope. Asynchronous Python scheduling, concurrent hosts, per-language sandboxing and automatic hot reload are **not** covered.

**Production boundary:** one native plugin format (ABI-3 `.so`); Python source is hosted implementation code, not an independently installed executable plugin. The `.so` is independently verified and owns its Python instance, registration and lifetime. Future production adapter must avoid the POC's unsafe TLS pointer and use generated revocable host scopes with explicit identity/grants per hosted logical plugin. This experiment is not P1 parity or a production interpreter sandbox.

## Local Linux acceptance

Run the CI recipe in `.github/workflows/graph-v2-python-language-adapter.yml`; it needs Rust 1.96.1, Python development headers/libpython and the normal Phenix root workspace build. The fixtures and graph test runner use a separate Cargo workspace. The only production API addition is the canonical graph section encoder.

Local embedding evidence (28 October 2026, Linux x86_64, Rust 1.96.1):

| Gate | Result |
| --- | --- |
| `cargo test -p phenix-contract` | 33 unit and 4 integration tests passed, including section framing, normalization, padding, invalid declarations and valid-but-oversize rejection |
| `cargo test -p phenix-artifact` | 2 unit tests passed, including malformed graph sections |
| Separate fixture workspace build, debug and release | Passed; fixture build dependencies use public SDK/contract sources only |
| Full graph runner with debug native artifacts | Passed |
| Full graph runner with release native artifacts after `strip --strip-all` | Passed, including descriptor-derived embedded graph equality and schema-spoof rejection |
| Offline release provider extraction with constructor witness enabled | Passed without creating the witness file |

These are bounded local results, not a full release/LTO/linker matrix or complete repository acceptance. This base has no `maintenance.nix`, `.stitch.json` or devenv configuration; `devenv test` and canonical `nix flake check -L` were not run. PR #1186 integrates the adapter native-drain fix (#1185) and readiness audit fixes (#1184); fresh exact-head full-DAG CI remains required before acceptance.

## Native panic drain regression

The direct Rust provider `panic` regression from #1183 remains enabled. Generated synchronous exports now report quiescent failure (ABI status 5) after unwinding; generated pending exports still report non-quiescent failure (status 2), since their workers may remain alive. The kernel continues to retain imported child leases independently of the parent's native completion. No failed-ticket shortcut is used.

Local validation on the fix branch passed the real native Python-to-Rust runner, including direct Rust panic, all 66 kernel unit tests, SDK and macro tests, and Nix checks `m1-pending`, `m1-pending-product`, `m1-imports`, `m1-lifecycle`, and `m1-lifecycle-product`. This is local evidence, not exact-head CI acceptance or full graph-v2/P1 parity. The workflow's existing experiment path filter covers this README change; SDK/runtime paths alone do not trigger it.
