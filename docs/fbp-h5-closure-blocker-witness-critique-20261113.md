# H5 concrete blocker witness — independent Phase 2 adversarial critique

Date: 2026-11-13. Reviewed proposal: `fbp-h5-closure-blocker-witness-design-20261113.md`.

1. **Witness is revalidated, not trusted.** A cached `Process(i)` only proves not-closed while `p.request == Some(R)` OR `closure_obligation(i,R)` currently holds. A cached `Queue(q)` only proves not-closed while `queue.request_count(R) != 0`. If either clears, DFS **must** run; no perpetual blocked result.
2. **Request identity:** Store witnesses in the request scope keyed by exact `RequestId`, not application IDs or node names. Release/cancellation drops the entire scope or leaves the map inert until release. No reuse between generations or physical sessions.
3. **No unsealed cache:** Before `close_request`, local closure must always be false. Do not cache that as a blocker. After sealing, no new roots are admitted, so relevance pruning remains sound; even so, cached negative witnesses never rely on this monotonicity for correctness.
4. **No positive cache:** Avoid treating an earlier `true` proof as an unconditionally permanent guarantee. The ordinary full DFS remains the only authority to declare request-local closure.
5. **Queue identity:** Include physical queue index, not packet offset. FIFO, middle `pop_at`, cancellation, atomic fanout and reader closure are already coordinated with #1276's exact committed request count. An expired queue witness must never hide other blockers; rerun DFS.
6. **Process identity:** A process may be active for another request, may restart under `RestartAffectedProcess`, or its request-local optional obligation may be marked observed. If the actual two-way predicate becomes false, recompute. Do not infer blocked merely from `p.done == false` or global WaitingWake without request ownership.
7. **Cycles/multi-roots:** A witness is a concrete direct queue/process condition found by the full visited-set traversal. The initial path's producer remains an ancestor in the compiled immutable topology; multiple sources and cycles are handled by the same original DFS. No caching graph traversal lists.
8. **Interior mutability:** `RefCell` is private to `RequestScope`; ensure no borrow lives across `closure_obligation` and no reentrant mutable borrow is possible through custom callbacks (the helper never runs a callback). If a shared Sync trait is required by the kernel, reconsider this design before implementation.
9. **Performance tradeoff:** In a large chain, a cached still-active blocker can replace an O(ancestors) DFS with a constant-size current-state probe. But a process blocker that rapidly changes can cause an extra map lookup plus normal DFS; fan-in with small reachable set may regress. Benchmark several sizes and do not declare H5 resolved from a microbenchmark.
10. **No behavior extension:** Never change readiness candidate ordering, `input_closed_for` result, `closure_fresh`, wire/type validation, result arbitration, request status or closure-of-open-ingress rules. The optimization must be invisible to callers.
11. **Exit path:** A failed session may drop queued packets and cancel request scopes; stale witnesses are not a reason to defer cleanup or leak leases. The map stores primitive indexes only and cannot keep processes or payloads alive.
12. **Phase 4 acceptance:** Scrutinize each original `return false` site (direct queue, active upstream process, upstream queue) for a correctly typed witness, and verify the final `true` path clears the cache. Review source diff and exact-head CI. Treat any new lock or unbounded cache as a design regression requiring Phase 1.

Disposition: approve the tightly scoped, revalidated **negative** witness mechanism with explicit measurement; leave H5 partial and disallow a permanent negative/positive closure assumption.
