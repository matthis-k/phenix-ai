# H4 obligation-aware idle prefilter — separate Phase 2 critique

Review of [Phase 0–1 design](fbp-h4-obligation-idle-design-20261113.md), before implementation.

1. **All-optional reservation requires no physical packet.** This is the key counterexample to blindly skipping reachable nodes. Existing `closure_obligation(index,id)` is the authoritative check for zero-packet scoped closures and must run on every candidate whose declared policy has `Optional { required: [] }`. Open/unsealed scopes may retain obligations conservatively. Reject any approach skipping solely because queues are empty.
2. **Ready, pending and active handoffs.** Never skip `Ready`, `WaitingInput`, `WaitingWake`, `Dispatched`, `PublicationPending` or `p.request.is_some()` in live scopes. The skip predicate is restricted to exactly `Idle` and no queued/pending publication; the no-request branch remains unchanged.
3. **Staged readiness / custom policies.** A `Readiness::Custom` policy may select a legal closed port without a native packet, and staged `WaitInput` can be pending. Exclude custom initial/override policies and any staged state from the scoped shortcut, even when a future refactor changes handoff ordering.
4. **Global EOS and closure.** A queue with a writer closed but temporarily empty can deliver EOS even when no active request owns the node. Require *all* physical writers open. No shortcut on zero-input source nodes.
5. **Multiple roots / cross-request isolation.** For each all-optional candidate, inspect every registered request's `closure_obligation`; one unrelated scope must never suppress an owned closure. Existing `reachable` already includes all successful roots. No cached negative result across calls.
6. **Wake / custom source work.** Source nodes and queued work remain excluded. For live scopes include the wake pending flag as an additional conservative guard if the process could be woken; do not treat an open input queue as sufficient to skip a wake-driven activation.
7. **Performance counterexample.** If every process is reachable and all-optional has a pending obligation, there is no safe shortcut. On each `refresh()`, inspecting the remaining obligations can still cost O(V) or worse. Paired benchmark must show practical benefit, not claim eliminating the O(V) scan.
8. **Tradeoff accounting.** The implementation should remove `all_reachable` only if doing so does not introduce an extra global per-process tree lookup in sparse scopes. For non-all-optional policies the skip decision must avoid request reachability probes altogether; for all-optional rely on `closure_obligation` with no additional state.

**Decision:** Accept for Phase 3 only with the predicate above. Keep the baseline H4 prefilter unchanged in no-request sessions. Limit code changes to `runtime/mod.rs` and an explicit test/benchmark exercise if needed. The main accepted limitation is that the full process inventory remains O(V); this scoped optimization cannot justify M7 acceptance by itself.
