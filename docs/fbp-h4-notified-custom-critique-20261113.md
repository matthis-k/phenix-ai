# H4 notified Custom — independent Phase 2 adversarial critique

Reviewed [the Phase 0/1 design](fbp-h4-notified-custom-design-20261113.md) separately from implementation.

1. **Default semantics remain polled.** A trait default of `false` is essential; existing `ReadinessPolicy` implementations can inspect external state and cannot be silently made event-driven. Both the build-time `always_poll` predicate and the on-demand `idle_inputs_cannot_progress` guard must be audited. The latter always returns false for any Custom by design; this does not itself add scheduling work when the node isn't dirty.
2. **Notifier must not set pending wake.** Reusing `WakeHandle::wake()` would resume `WaitingWake`, an observable correctness bug. A distinct `ProcessNotifier` is justified as it invalidates readiness only. Reuse the same lock/target index set; do not build a second queue, permission system or worker.
3. **Atomicity / race:** `notify` must check both `WakeSignal.active` and `WakeSlot.active` while holding signal mutex, publish target ID and advance aggregate `WakeListener` epoch under that lock. `refresh()` takes targets before scan, never acknowledges a wake arriving afterward.
4. **Recovery and stale references:** `RequestFailurePolicy::RestartAffectedProcess` replaces `WakeSlot`. Old process notifier cannot notify newly spawned state. A fresh `session.process_notifier(path)` can. A finished session rejects all notifiers.
5. **Shared external state:** a custom policy that reads mutable state must notify on *every transition capable of changing selection*. Notification can occur before or after the setter; memory ordering must be supplied by the policy's external synchronization plus the WakeSignal lock. A false opt-in is explicitly a plugin defect.
6. **Scoped request closure:** a custom selector may use `InputHead.closed` when a sealed upstream scope stops owning a request without a global EOS. Watch each sealed scope's reachable notified Custom node just like Optional. Default Custom remains always-polled. Rename the map accordingly or document the semantic expansion.
7. **Request start / seal:** `close_request` already marks every reachable process dirty, but without a dynamic watch an upstream `Step::Complete` could unblock a custom join with no queued event. Retain watch until release/cancellation. Repeated close must remain idempotent, overlapping scope counts separate, cancellation detach before reachability clears.
8. **Staged waits:** `Step::WaitInputs` and `Step::WaitInput` join `always_poll` permanently. Do not use an opt-in trait method to suppress staged closure errors or program-defined readiness transitions.
9. **Unaddressed host notifier:** `SessionNotifier::notify` must continue bumping `global_epoch` to force full scan for arbitrary state changes. Only a process-scoped notifier avoids that scan.
10. **No-op notify and listener contract:** sending a process notify for a process with nothing to select still wakes `WakeListener`; it is a change notification, not success or a ticket. Return bool only for active registration, not for work completed.
11. **O(V) path lookup:** `process_notifier(path)` may use the existing `wake_handle` compiled path lookup; it is a one-time host capability acquisition, not per-event scanning. Avoid introducing a permanent path map unless benchmarks demand it.
12. **Policy method invocation under startup:** `notification_driven` is user-supplied code. It may panic or block. Existing Custom `select` panic handling is explicit; query the new flag at session creation with `catch_unwind`, recording a deterministic session initial failure rather than panicking out of start. Since trait method returns bool, it should be side-effect-free and documented.
13. **Small-graph performance:** lock targeting adds per-notification BTreeSet cost while saving full refresh for large mixed graphs. Benchmark representative 1-node and 256-node workload and record regressions, not just 256-node gains.
14. **Optional requirement:** an opt-in Custom can still select only actual legal available or proven-closed heads. The notifier must not fabricate request candidate heads; selection validation is unchanged.

**Disposition:** conditional approval if implementation preserves original default policy polling, notifier-vs-wake semantics, idempotent request watch, stale handle protection and panic containment. If adding this behavior introduces another public readiness variant or a second wake queue, return to Phase 1. Phase 4 requires exact-head CI and new + existing perf evidence, with accepted limitations rechecked.
